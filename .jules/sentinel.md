## 2026-08-01 - SSRF Vulnerability in User Configured URLs
**Vulnerability:** The application takes user configurable URLs (`AIDR_BASE_URL` and `ollama_url`) and makes HTTP requests to them without validating the hostname to ensure it does not resolve to an internal/private or metadata service IP.
**Learning:** Configurable external endpoints are just as vulnerable to SSRF as user-submitted webhooks or file fetchers. Python's `requests` library will automatically resolve and follow redirects to internal addresses if not explicitly prevented. Furthermore, we must carefully handle DNS resolution timeouts (`socket.getaddrinfo`) using `ThreadPoolExecutor` instead of modifying global socket timeouts.
**Prevention:** Any user configurable URL that the server reaches out to must be validated. Create a unified `validate_url` function to explicitly parse the scheme, resolve the hostname (with a timeout mechanism), and check the resolved IP against a blocklist of private, loopback, metadata, unspecified, link-local and multicast IPs, taking into account whether private IPs should be allowed depending on the specific use case (e.g. Ollama can be running on localhost).
