## 2025-02-14 - Prevent SSRF in User-Configurable URLs

**Vulnerability:** The application accepted user-configurable URLs (AIDR base URL and Ollama URL) without validation. This allowed Server-Side Request Forgery (SSRF), where an attacker could provide URLs pointing to local services (e.g., `localhost`) or cloud metadata endpoints (e.g., `169.254.169.254`), tricking the server into making requests on their behalf. This could lead to information disclosure or unauthorized access.

**Learning:** When validating URLs to prevent SSRF, simple string matching or checking just `is_private` / `is_loopback` is insufficient. The scheme must be strictly validated (`http` or `https`). Also, `is_unspecified` (`0.0.0.0`) and metadata IPs must be explicitly blocked because they bypass private/loopback checks but still route locally. Furthermore, this validation via `socket.getaddrinfo` is a basic mitigation for generic SSRF but does not fully protect against DNS Rebinding (Time-Of-Check to Time-Of-Use or TOCTOU). Full TOCTOU mitigation typically requires a custom HTTP adapter that resolves and pins the IP at connection time, which is complex.

**Prevention:** Ensure all user-configurable URLs are validated before use. Validate that the parsed scheme is strictly `http` or `https`. When using `ipaddress` for filtering, explicitly check and block `is_unspecified` addresses and metadata IPs in addition to `is_private` and `is_loopback` (unless private IPs are explicitly needed for legitimate local usage like Ollama). When resolving hostnames, use `socket.getaddrinfo` within a `ThreadPoolExecutor` and explicitly cancel futures on timeout or failure to prevent resource exhaustion or thread leaks.
