## 2025-02-15 - Missing authorization checks in chat endpoints
**Vulnerability:** Insecure Direct Object Reference (IDOR) where chat endpoints like `get_chat`, `delete_chat`, `rename_chat`, and `chat` didn't verify if the requesting user's `session_id` matched the chat's owner. Furthermore, `session_id` was only initialized in the index route, leading to potential uninitialized session variables that could bypass auth checks if directly accessed.
**Learning:** Never trust client-provided IDs for data retrieval without confirming ownership. Authorization must be explicitly verified on *every* mutating or data-exposing endpoint. Moreover, ensure tracking variables like `session_id` are initialized via global hooks (e.g., `@app.before_request`) rather than lazily on specific frontend routes.
**Prevention:** Store the creating user's identifier alongside the resource, and explicitly enforce an authorization check (`resource.user_id == current_user_id`) in all endpoints that access or modify the resource. Use global hooks for crucial state setup.
