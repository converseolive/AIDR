## 2024-07-24 - Missing Object-Level Authorization (IDOR) on Chat Sessions
**Vulnerability:** Chat sessions were globally shared across all users. `list_chats` returned all chats for all users, and endpoints for viewing (`get_chat`), renaming, deleting, and appending messages (`chat`) did not verify if the requesting user owned the chat, leading to an Insecure Direct Object Reference (IDOR) vulnerability. Furthermore, user identity (`session_id`) was only initialized if the user explicitly hit the `/` index route, causing direct API requests to bypass identity altogether.
**Learning:** In stateful Flask applications, identity verification must be initialized globally (e.g. via `@app.before_request`) to prevent authorization bypasses on direct API calls. All data retrieval and mutation endpoints must explicitly authorize the requester against the object's owner.
**Prevention:** Always initialize user tracking at the application middleware level. Tag all created objects with the creator's ID, and continuously verify `object.user_id == current_user_id` on all read/write endpoints.
