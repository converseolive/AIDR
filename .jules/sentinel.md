## 2025-03-01 - Prevent Authorization Bypasses by Initializing Sessions Globally
**Vulnerability:** Insecure Direct Object Reference (IDOR) and authorization bypass in chat endpoints. The `session_id` was initialized only when a user accessed the `index()` route, and subsequently, API endpoints like `get_chat`, `delete_chat`, `rename_chat`, and `chat` didn't verify if the requesting user owned the chat. An attacker could bypass authorization by accessing the API endpoints directly (which leaves their session_id as None) or spoofing requests for other users' chat sessions.
**Learning:** Initializing session variables critical for authorization within specific route handlers (like `index()`) is dangerous, because users can hit API endpoints directly without visiting the initialization route first.
**Prevention:** Initialize critical session identifiers globally using a `@app.before_request` hook so that it's guaranteed to be set for every request. Always verify that state-mutating and data-retrieval endpoints ensure the `session_id` of the resource matches the `session_id` of the requester.
