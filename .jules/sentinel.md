## 2024-07-02 - Missing Authorization Validation in Chat Endpoints (IDOR)
**Vulnerability:** A critical Insecure Direct Object Reference (IDOR) existed across multiple chat endpoints (`get_chat`, `delete_chat`, `rename_chat`, `clear_chat`). The application tracked users with a global session ID (`session.get("session_id")`), but the chat state dictionary did not tie chats to their creator's session. This allowed any user to access, rename, clear, or delete any chat simply by providing its ID.
**Learning:** Even if objects are generated with hard-to-guess UUIDs, if those IDs ever leak or if no ownership check is enforced when accessing an object, an IDOR vulnerability arises. Global states must map resources securely to individual session boundaries.
**Prevention:** Always attach an owner identifier (like `session_id` or `user_id`) to every created resource. When accessing or modifying a resource, strictly enforce an authorization check to verify that the requesting user's identifier matches the resource's owner identifier.
