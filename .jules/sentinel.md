## 2025-02-12 - [Critical] Insecure Direct Object Reference (IDOR) on Chat Sessions
**Vulnerability:** A critical IDOR vulnerability allowed any user to access, view, rename, and delete chat sessions belonging to other users. This occurred because `chat_sessions` was a globally accessible dict and user ownership was not validated on API requests for `/api/chats/*`.
**Learning:** Initializing user identifiers (`session_id`) loosely inside route handlers like `index()` rather than globally via `@app.before_request` leaves direct API accesses uninitialized (`None`). If ownership checks compare uninitialized request sessions to `None` owners, attackers can bypass authorization natively.
**Prevention:** 1. Initialize user sessions globally using a `@app.before_request` hook. 2. Always persist a strict `user_id` identifier inside state-mutating objects (like `chat_sessions[id]`). 3. Explicitly compare object `user_id` against the authenticated request `session["session_id"]` in all CRUD endpoints.
