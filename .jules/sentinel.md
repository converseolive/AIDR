## 2024-07-17 - Prevent IDOR by Binding Identifier and Validating at @before_request

**Vulnerability:** Insecure Direct Object Reference (IDOR) allowed users to read and manipulate other users' chats by providing a valid but unauthorized `chat_id`. The root cause was twofold: the `session_id` representing the user was only initialized on the `/` index route, meaning direct API callers might not have one, and chat objects did not store or enforce a strict relationship with the creator's `session_id`.
**Learning:** In Flask apps relying on session variables for identity, failing to initialize the identifier globally (e.g. within an `@app.before_request` hook) creates scenarios where session checks can inadvertently evaluate to `None == None`, allowing authorization bypasses on state-mutating and retrieval endpoints.
**Prevention:** 1) Always initialize user identifiers (like `session_id`) using an `@app.before_request` hook. 2) Bind the user identifier to stateful objects during creation. 3) Consistently verify that the authenticated user identifier matches the object owner's identifier before returning data or applying changes in every state-mutating and retrieval endpoint.
