## 2024-07-25 - [Fix Insecure Direct Object Reference in Chat Endpoints]
**Vulnerability:** Chat sessions were being created without strong association to a user's session identifier. Subsequent endpoints (`get_chat`, `delete_chat`, `rename_chat`, `chat`) fetched these objects merely by their unguessable IDs (UUIDs) without verifying if the requesting user actually owned them. Additionally, user identity (`session_id`) was previously instantiated only on the `/` (index) route, allowing an authorization bypass where API consumers directly calling API endpoints without visiting `/` could manipulate chat state with `None` session IDs.
**Learning:** Never rely exclusively on random/unguessable IDs for access control (IDOR). Also, tracking user identity via session variables must be done globally (e.g. via `@app.before_request`) rather than inside specific route handlers to prevent sessionless bypasses.
**Prevention:** Always persist the `user_id` inside data objects upon creation and consistently verify `object.user_id == current_session_user_id` on all endpoints before reading or mutating the object. Use global middleware for critical initialization like identity tracking.
